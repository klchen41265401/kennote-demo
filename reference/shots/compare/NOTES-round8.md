### 三之八、第八輪（視覺 QA 第八輪）

> 前七輪的紀錄原封不動保留在上面。
> **本輪最重要的一件事：推翻第七輪交接單 §2-A 的整個診斷。**
> 那份寫「Notion 的 tab 列下框線在 y93..94（2px）、表頭列高 55px、kennote 只有 32」，
> 要我們把表頭列 32 → 55。**三個數字全錯**，照做會把四張圖一起弄壞。
>
> 這一段手寫在 `reference/shots/compare/NOTES-round8.md`，由 `e2e/compare.spec.ts` 接到 README 最後面。

#### ⭐ 根因一：第七輪「表頭列 55px」是把工具列的像素當成框線量到的

第七輪是用 `colseg 07-db-table dark 600`（單一行）下判斷的。x600 在 y93..94 確實有
2px 的 `rgb(241,240,240)`——但那是**右上角工具列元件的一小段**，不是橫貫全圖的框線。

本輪改用「逐列掃**同色連續 ≥ 300px** 的橫線」（20 行的臨時腳本，值得補進 `measure.mjs`），
`07-db-table-light` 的結果是：

| | Notion | kennote（第七輪） |
|---|---|---|
| 作用中 tab 膠囊 | y79..110（高 32）| y76..107（高 32）✓ |
| **tab 列下框線** | **整張圖一條都沒有** | y112（1px，704px 長）✗ |
| 表頭列 | y118..149（高 32）＋ 下框線 y150 | y113..144（高 32）＋ 下框線 y145 ✓ |
| 表頭欄名字身 | y127..138 | y124..135 |
| 資料列 | 36 ＋ 1 格線 | 36 ＋ 1 ✓ |

也就是說 **列高、格線色、格線間距、表頭列高（32＋1）四樣本來就全對了**，
真正錯的只有兩件事，各 2 ~ 3px：

1. **膠囊下緣 → 表頭列上緣**：Notion **7px**、kennote **5px**。
2. **整個資料庫在裁切圖裡高 3px**（標題、膠囊、表頭字身全部一致差 3）——裁切原點。

「Notion 沒有 tab 下框線」有四張圖互相印證，不是單張的雜訊：

* `07-db-table` light / dark：y110（膠囊下緣）→ y150（第一條格線）之間一條線都沒有；
* `07b-db-header-hover`：Notion 只有 y85 / y122 兩條格線，kennote 多一條 y52；
* `07n-db-view-tabs`：Notion 全圖沒有任何 ≥300px 的橫線，kennote 有 y106。

→ `DatabaseHeader.module.css` 的 `.bar`：**拿掉 `border-bottom`、`padding-bottom` 4 → 7**
（整條 bar 37 → 39，膠囊不動、表頭以下整體下移 2px）。
第七輪特地把這條線的深色改成 `rgb(44,44,43)` ——整條線都不該存在。

→ `compare.spec.ts` 六個資料庫視圖共用的 `padY` **13 → 16**（那 3px 是裁切原點）。

**四張圖的最佳位移 dy 全部歸零**：
`07-db-table` `+4,-5` → `+4,+0`、`07b` `+2,+3` → `+2,+0`、
`07c` `+4,-5` → `+5,+0`、`07d` `+4,+0` → `+4,+0`（本來就 0）。

> ⚠️ `07b`（錨在表頭列）與 `07d`（錨在第二列的儲存格）的 `padY` **不用動**：
> bar 長高 2px 會同時把它們的錨點往下推 2px，裁切自動吸收。
> 只有錨在「資料庫 block 上緣」的 `07*`（padY 13→16）與 `07c` 要改。

#### ⭐ 根因二：`07c` 的 Notion 參考 hover 的是**第二列**

`07c-db-row-hover` 掛了四輪（9.2）。橫線一比就出來：

| | y 的橫線 | 間距 |
|---|---|---|
| Notion | 7 / 44 / 81 / 118 | 37 / 37 / 37 |
| kennote（padY 40、hover 第一列）| 6 / 39 / 76 / 113 | **33** / 37 / 37 |

kennote 的 y6 是 tab 下框線、y39 才是表頭下框線（中間 33 ＝ 表頭列高）；
Notion 的 y7 卻是「**上一列的下框線**」——Notion 那張根本沒拍到表頭，
hover 的是**第二列**（`y45..80`，左側 ⠿ 把手已經出現）。

→ `compare.spec.ts`：hover 改成 `.nth(1)`、`padY` 40 → **45**。
這樣 kennote 變成「表頭下框線 7 / 第一列 8..43 / 44 / **hover 的第二列 45..80** / 81 / 118」，
四條線全部對上（跟第五輪發現 `07d` 拍的是第二列是同一個坑）。

**`07c` light 9.2 → 6.1、`+4,-5` → `+5,+0`。**

#### ⭐ 根因三：Notion 的資料庫列 hover **不染色**

`07c-db-row-hover-light` 被 hover 的那一列（把手已出現）整列底是 **`rgb(255,255,255)`**，
名稱欄（x75）也是白的。kennote 原本整列 `rgb(249,248,247)`、名稱欄再深一階
`rgb(240,239,237)`，704×36 的色塊佔 `07c` 的 24% 面積，平均通道差光這塊就 ~2。

→ `TableView.module.css` 拿掉 `.row:hover` 與 `.row:hover .frozen` 的 `background`。
hover 只留左側 ⠿ 把手與「⤢ 開啟」按鈕 —— Notion 也只有這兩個。

#### ⭐ 根因四：簡易表格的標題列**根本沒有底色**，而深色的那個底色剛好 ＝ 格線色

`colseg 05-14-table light/dark 300`：

| | Notion | kennote |
|---|---|---|
| 標題列底（light）| **rgb(255,255,255)**（＝頁面底）| rgb(249,248,247) |
| 標題列底（dark）| **rgb(25,25,25)**（＝頁面底）| **rgb(56,56,54)** |
| 格線 | rgb(230,229,227) / rgb(56,56,54) | 一樣 ✓ |

深色的 `--kn-editor-callout-bg` 剛好等於格線色 `rgb(56,56,54)`，
整條標題列變成一塊 **704×36 的實心色塊**，連欄分隔線都被吃掉
（`row 05-14-table dark 35` 的 K 側只有 `x246..949 rgb(56,56,54)` 一段）。
`05-14-table` dark 的明顯差異像素 15.4% 裡有 11% 就是這一塊。

→ `editor.css` 的 `.kn-table th.kn-table-cell` `background` 改 **`transparent`**（粗體保留）。
另外橫格線 Notion 在 y30/65/100/135、kennote 在 y28/63/98/133（列高 34 兩邊一樣），
是 bbox 置中差 2px → `compare.spec.ts` 的 `05-14-table` 補 `dy: -2`。

**`05-14-table` light 4.3 / 5.9% → 2.8 / 3.6%；dark 6.9 / 15.4% → 3.0 / 2.9%。**
（深色的明顯差異像素直接掉到 light 之下，全場最大的單項改善。）

#### `07-db-table` 的 **dark 參考也是開著選單的**

`colseg 07-db-table dark 150`：`y114` 一條 `rgb(56,56,54)` 框線、
`y115..184` 一整塊 `rgb(37,37,37)`、橫向 `x48..267` —— 跟第五、六輪認定「比不了」的
`07b`/`07c`/`07d` dark 是同一個浮層，蓋掉了表頭與前兩列的名稱欄。

這解釋了為什麼本輪 light 6.2 → 5.7、dark 只有 10.5 → 10.3。
**`07-db-table` dark 的下限大約在 10**，已列入 KNOWN_GAPS，之後看 light 就好。
